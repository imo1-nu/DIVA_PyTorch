# TorchDIVA / DiffWave 実装比較

確認日: 2026-10-23。長時間のデータ生成・学習に進む前の監査。
この文書は監査時点の草稿を記録したもの。指摘への対応と正式な2条件の設定は
[README.md](README.md)、実行履歴は [RUN_LOG.md](RUN_LOG.md) を参照。
**現状は論文と同一条件の再現ではない。特に、音声合成のベースラインとDiffWaveの重みが異なる。**

## 1. 著者版と main の違い

既存の `src/*.py` で実装が変わったファイルは `diva_vocaltract.py` のみ。
Motor Cortex、SSM、Cerebellum、誤差マップなどのソースは著者版と同一。
ただし、声道出力がフィードバックされるため、制御コードが同じでも学習軌道まで同じとは限らない。

| 箇所 | 著者版 | main | 再現結果への影響 |
| --- | --- | --- | --- |
| 聴覚フィードバックのF0 | `100 + 50 * art[11,0]`。圧力の成分を参照 | `100 + 50 * art[10,0]`。F0の成分を参照 | 音響特徴だけでなく逆写像と運動学習にも影響する |
| 声門源の1周期 | `fixed_sample_size=True` により92サンプル固定 | `ceil(fs/f0)` による可変長 | ピッチと励振波形が変わる |
| 音声生成の乱数 | `debug_no_rand=True`。`rand_exports.mat` の固定値を使用 | NumPyの乱数を生成 | 雑音・周期間変動・生成波形が変わる |
| 前周期との補間 | 旧インデックス計算 | MATLABの1始まりの式を0始まりへ変換 | 可変周期間のつなぎ方が変わる |
| 返す波形長 | 作業バッファの長さを返す | 指定長に切り詰める | 評価時の長さ・端点が変わる |

F0修正には根拠があり、MATLAB参照ソースは `Art(end-2)` を使用する。
しかし、**修正が妥当であることと、著者の公開TorchDIVAと同じ結果になることは別問題**。
今回通過した4件の音声合成テストは修正の回帰テストであり、論文のMATLABとの数値一致を再検証したものではない。

同一の運動入力で実際の関数を比較した結果:

| F0制御値 | 圧力制御値 | 著者版のF0 | mainのF0 |
| --- | --- | --- | --- |
| -0.5 | 0.6 | 130 Hz | 75 Hz |
| +0.5 | 0.6 | 130 Hz | 125 Hz |
| 0 | 1 | 150 Hz | 100 Hz |

この検査のF1–F3と体性感覚出力は差分0だった。
これは同一入力の声道関数の検査であり、学習後の運動指令や音声全体の同等性を示さない。

### 保存済みの重みも一致しない

`src/diva_weights_*.mat` の6ファイルが変更されている。
例えば `SSM2FF.W` は著者版が `101×13`（非ゼロ1188要素）、mainが
`61×13`（全要素ゼロ）。他の重みも時間方向が101から61に変わっている。

これらは各ターゲットの実行時に `PrepareSimulation()` が書き直す作業用の重みでもある。
通常の初期化を経ればこの保存状態がそのまま使われるとは限らないが、単独モジュールのテストや
重みを直接読む処理では影響する。同じ初期状態だと仮定して比較してはいけない。

そのほか、Civier (2010) 用の実験コード、`bid` / `bad` / `good_dog` のターゲット、
Praatやカスケード共鳴器による合成が追加されている。これらはTorchDIVA論文の
DiffWave実験そのものではない。今回の草稿は原著の `diva_synth(..., 'sound')` を利用し、
Praat音声・固定110 Hzの代替合成音声は入力に使っていない。

## 2. 今回の実験草稿と著者版・論文の違い

### 結果を比較する前に解決が必要な点

| 項目 | 論文・公開コードで確認できたこと | 草稿の状態 | 判定 |
| --- | --- | --- | --- |
| DiffWave重み | 公開TorchDIVAブランチには対応する学習コード・CNN重みがない | SpeechBrainのLJSpeech用重みを使用 | 同一重みではない。代替条件 |
| 学習済みモデルの読込 | 著者のチェックポイントを同定できない | 254テンソルを厳密読込。SHA256照合済み | 形状の互換性のみ確認。原著との数値的同等性は未確認 |
| 畳み込みの境界処理 | LMNTはゼロ埋め。SpeechBrainは反射埋め | SpeechBrainに合わせて反射埋めを設定 | 代替モデルに必要な仕様差 |
| CNNの層構成 | Zhang本文は前半8層のCNNと記載。一方、全体15層・図2の数え方には曖昧さがある | 前半7層のCNN、全体15層に解釈して実装 | **前半8層という本文とは一致しない。確認前に学習すべきでない** |
| データ分割 | 公開リストは学習482件、評価10件 | 取得したファイル集合は一致 | ファイル単位では一致 |
| 検証データ | 原著の検証分割・早期終了条件は確認できない | 学習リストを438件の学習＋44件の検証に分割 | 追加した条件。全482件で学習する条件とは異なる |
| 学習長 | 原著補助Excelに `Epochs=1000`、生成パスに `ckpt_epoch001000` の表示がある | 最大50,000ステップ、早期終了を設定 | 1000エポックと同一とは言えない |
| 精度・最適化 | TorchDIVA論文に十分な指定がない | BF16、Adam、学習率0.001、勾配クリッピング | 追加した条件。学習率は参照論文由来でTorchDIVA固有条件ではない |
| 音声の時間合わせ | 公開ターゲット抽出コードは2秒固定。元音声は約0.51〜4.52秒 | 共通長に中央切り出しし22.05 kHzへ変換 | 論文に明記のない前処理。評価値に影響し得る |
| 評価 | 論文はPESQ、CSIG、CBAK、COVL、segSNRと対応のあるt検定を使用 | 評価処理・実験結果は未作成 | 再現完了ではない |

CNNの8層／15層の矛盾は、今回の草稿だけで解決した扱いにしない。
著者の原実装を入手できない場合は、解釈した構造を明示し、別条件として扱う必要がある。

### 実行のために加えた修正

実験ブランチでは、次の3ファイルに未コミットの変更がある。

- `src/diva_cerebellum.py`: 初期ゼロバッファを101固定からターゲットの長さへ変更。
  2秒ターゲットの初期化で起きる範囲外参照への対応。
  別ブランチ `fix/long-target-initial-buffer` は `max(101,num_steps)` としており、
  短いターゲットの従来の長さを保持する点で草稿と異なる。両者を無条件に同一視しない。
- `src/diva_targets.py`: 数値で渡された最小値・最大値を初期化。
  著者の自動抽出処理から渡されるfloatで `UnboundLocalError` になる問題への対応。
  数式を変える意図はないが、回帰検証は未完了。
- `src/diva_vocaltract.py`: 声道形状計算のCUDA固定を入力テンソルのデバイスに変更。
  データ生成をCPUで実行するための変更。CPU/GPU間の丸め差の比較は未実施。

これらは、前節のmainに既に入ったF0・合成周期の変更とは区別する。

### 草稿の監査で見つかった追加の不備

- `data.py` でファイル別seedを設定した後に `DIVA()` を作っているが、
  そのコンストラクタがNumPyとPyTorchのseedを0へ戻す。保存しているseed値を
  実際の使用seedとして扱えない。生成済み2件は動作確認用で、正式結果には使わない。
- ペアの再利用判定に、人の音声と生成WAVのハッシュはあるが、生成実装・設定の
  指紋がない。声道の仕様を変えた後に旧ペアを誤って再利用する余地がある。
- マニフェストの `speaker_id` / `session_id` は旧ファイル名の位置から暫定的に付与している。
  現行SVDのメタデータで意味を確認するまで、話者単位の汎化を主張しない。

## 3. データと原著側の記述で注意すべき点

学習リスト482件と評価リスト10件には、同じファイルの重複はない。
ただし、ファイル名先頭のSVD ID `1` と `2` は双方に含まれる。
これは今回加えた分割による混入ではなく、公開リスト自体の性質。
そのため、ファイルを保持した評価と、話者を完全に分離した評価を混同しない。
先頭IDの種類は合計52であり、論文の「50人」と機械的に同じ数にはならない。

論文Discussionは `492 train, 10 test` と述べるが、実際の公開リストは
**482 train + 10 test = 492 total**。今回の草稿はファイル一覧を採用している。
SVDから取得した492件は、NSPのPCMと変換後WAVのPCMが全件完全一致することを確認した。

### 補助Excelの値にも不一致がある

著者公開の `test/figure_data/figs_1000.xlsx` 内には、異なる結果集合が共存する。
下表は数式の再計算ではなく、保存されている値と10件の個票の平均を照合した結果。

| 指標 | TorchDIVA個票の平均 | epoch1000のDiffWave個票の平均 | SummaryのDiffWave平均 |
| --- | ---: | ---: | ---: |
| PESQ | 1.060679 | 1.063572 | 1.622332 |
| CSIG | -5.543771 | -1.285600 | 2.841389 |
| CBAK | -0.372550 | -0.792772 | 1.566985 |
| COVL | -2.974668 | -1.034217 | 2.111011 |
| segSNR | -4.347635 | -3.120168 | -5.573690 |

CSIGのDiffWave平均が本文の一箇所では約-1.3、別箇所では約+2.841なのも、
この二つの集合に対応する。segSNRも後者では値が低下するため、
「全指標改善」をそのまま再現の合否条件に使うのは適切でない。
また、負のCSIG等が公表されているため、評価ライブラリが複合指標を1〜5へ
切り詰めるかどうかの違いも、事前に明示する必要がある。

## 4. 実験を再開する際の推奨順序

1. 著者公開版に必要最小限の実行環境対応だけを加えた条件を、原著比較用の基準にする。
   mainのF0・可変周期・乱数修正版は、修正版として別に測定する。
2. 保存済み重みを実行時の作業領域から切り離し、ターゲットごとに同じ初期状態を生成する。
3. CNNの層構成、seed、ペアの再利用判定を確定してから正式ペアを生成する。
4. 論文固有のチェックポイントを確保できなければ、SpeechBrain版は代替重みと明示する。
   公開リスト、1000エポックの手がかり、未記載の条件と追加仮定を記録する。
5. 原著Excelの個票とSummaryのどちらを比較対象にするかを明確にし、評価条件を固定する。

この監査時点では、2件の生成動作確認まで。CNN学習・音質評価は未実行。
元の音声合成比較作業の未コミット17ファイルは、整理前のSHA256と全件一致した。

数値の根拠は [audit_evidence.json](audit_evidence.json) に保存した。
